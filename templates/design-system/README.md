# Design system

The design system this project is built against, and where each kind of source for it
lives. Agents load the same facts from this folder and from `ux/architecture.md`.

The project needs a source of truth for tokens. Figma is the default: export variables
from the library file into [`figma/tokens/`](figma/tokens/). A team can instead maintain
tokens in this repo or a separate repository and feed both the project and Figma, or use
another design tool, as long as the tokens are stored here.

## Figma files

The links to the two Figma files live in `figma` in `ux/config.json`, not here:

- `site`: the site file, with the pages and features to implement.
- `library`: the library file, with the core styles. Tokens are exported from here.

The value is `false` when the project doesn't use Figma, and `null` while that is
undecided. Run `/ux-setup` to record the links.

The library file may or may not define variables. Anything it doesn't define as a
variable belongs in `supplemental/` or `guidelines/`.

## In this folder

| Folder | What goes in it |
| --- | --- |
| [`figma/`](figma/) | Everything that comes straight out of Figma. [`tokens/`](figma/tokens/) holds the variables exports and their unpacked JSON; [`assets/`](figma/assets/) holds exported mockups, images, icons, and the like. |
| [`supplemental/`](supplemental/) | Extended tokens and assets that are not literally Figma variables: sourced from production code, maintained by hand, or anything else. |
| [`guidelines/`](guidelines/) | Written patterns and guidelines that tokens don't define, one file per topic (color, typography, layout, components, …). |
| [`platform-components/`](platform-components/) | Component ports for the platform export. |
| [`exports/`](exports/) | Generated hand-offs: `DESIGN.md`, and the platform packages. |

Also at this level:

- [`token-usage.json`](token-usage.json) — the token usage map: what each group of tokens
  is for, in a form `validate` checks. Maintained by the design-system owner.
- `deviations-backlog.md` — generated by `validate`; appears after the first run.
- `token-usage-review.md` — findings from the `/token-usage-review` skill; appears after
  the first finding.

How the design system is implemented and validated in code is described in uxagent's
design-in-code reference, listed in the uxagent section of `AGENTS.md`. How this project
does it is in `ux/architecture.md`.

To hand the system to another AI tool as a DESIGN.md, run `/export-design-md`. It writes
`design-system/exports/DESIGN.md` from this folder.
To package the same docs for Lovable, Replit, Bolt.new, v0, and Figma Make, run
`npx uxagent export platforms`, or ask for the `design-system-export` skill. The packages
land in `design-system/exports/platforms/`. How those platforms ingest a system is in
uxagent's design-system platforms notes, listed in the uxagent section of `AGENTS.md`.

After a new Figma export, use the `design-tokens` skill.
